# Admin-managed Brain tools

SMA* site administrators open **Brain → select a section → Manage tool access**, or the **Tools · Admin** button. Controls, tool catalog, audit history and Synergy MCP source inspection are admin-only on both the page and API. Normal members retain access to research missions and their own libraries; an assigned agent can use its permitted shared sources while serving them.

Assignments apply site-wide. For a tool call to execute, both the calling agent's assignment and the tool's owning module gate must be enabled. Retrieval gates Market context, Economic calendar, Knowledge library, Trading journal and Synergy MCP. Memory gates Approved memory; Risk gates the Risk calculator; Robinhood gates broker tools. Turning off a module tool blocks that tool for every agent. Changing permissions affects the next invocation, including in running missions; it cannot undo a completed call or retract data already in the current context.

Synergy MCP starts unassigned for every agent, with its Retrieval gate off. Enable it on Retrieval and then on any desired agent. No automatic Synergy search occurs. Planner and Critic now support bounded tool requests before producing their plan/review, while Researcher and Strategist use their existing action loop. All stages use the same model-call, step, time and token budgets. Demo/evaluation runs still avoid the shared source database.

Role ceilings remain enforced: only Strategist/Critic can call the risk calculator, and only Strategist can prepare a broker proposal. No assignment permits order submission, arbitrary code/SQL, access to another operator's journal, or bypassing a broker approval. Disabling the Risk tool prevents a proposal from becoming ready; the deterministic final calculation still runs. Missing context/calendar evidence retains the existing wait gates. Knowledge and Memory controls govern agent retrieval, not the operator's manual source editing or research-approval workflow.

`GET /api/brain/tools` returns reviewed tool metadata, all eight sections, connection status and the saved policy. `PUT /api/brain/tools/:section` requires Admin plus CSRF and accepts exactly `{version, tools}`. Unknown sections/tools, duplicate entries and role-ineligible tools return 400. A stale revision returns 409; reload before overwriting another admin's changes. Saves record the authenticated actor, timestamp and before/after assignments; the most recent 100 changes are retained. The registry reads this policy before listing or invoking tools; storage failure fails closed. Source diagnostics remain at `/api/brain/synergy/search` and `/read`, restricted to admins.

PostgreSQL migration `008_brain_tool_policy.sql` adds a separate singleton configuration table. Apply through the guarded migration process after a database backup. Local SQLite stores the same policy in the workspace database. Existing personal workspaces, credentials, research history and Synergy MCP archive data are unchanged. The database URL stays server-side and continues to use its existing restricted read-only login.

Tests cover anonymous/member denials, CSRF, concurrent admin conflicts, persistence after reopening, actual execution by all agent roles, mid-run revocation, mandatory risk gates, and safe source rendering. Real PostgreSQL policy tests require a disposable `brain_tools_test` database through `TEST_BRAIN_TOOL_POLICY_DATABASE_URL`. Source-reader tests use the separate disposable `synergy_reader_test` database.
